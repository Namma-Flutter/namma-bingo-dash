## Architecture Overview

**State management**: Riverpod (`flutter_riverpod`). All providers live in `lib/providers/app_providers.dart`. The app uses `ProviderScope` at the root.

**Navigation**: `go_router` with a `ShellRoute` wrapping the three bottom-nav tabs (`/`, `/connections`, `/qr-generator`). Routes outside the shell (`/profile`, `/camera`, `/webview`) render full-screen. Navigation args are passed via `state.extra` as `Map<String, dynamic>`.

**Key providers**:
- `currentUserProvider` (`StateNotifierProvider<CurrentUserNotifier, User?>`) — persists the local user to `SharedPreferences` as JSON.
- `questionsProvider` (`FutureProvider<List<String>>`) — fetches the bingo questions from Firebase Realtime Database (`questions` node, shuffled on load).
- `bingoBoxesProvider` (`StateNotifierProvider<BingoBoxesNotifier, List<BingoBox>>`) — tracks each box's scan state, persisted to `SharedPreferences`.

**QR flow**:
1. User taps a bingo box → navigated to `/camera` with `{boxId, questionIndex, questionText}` extras.
2. `CameraScreen` uses `mobile_scanner` to decode a QR payload signed with `BINGO_USER_V1` + `namma_bingo_app` identifiers.
3. On successful decode, `bingoBoxesProvider.notifier.selectBox(...)` is called and `currentUserProvider.notifier.addScannedBox(boxId)` updates the user's scanned set.
4. `QrGeneratorScreen` renders the current user's data as a QR using `qr_flutter` and allows download via platform-conditional helpers.

**Platform-conditional download**: `lib/utils/download_helper.dart` re-exports either `download_helper_mobile.dart` or `download_helper_web.dart` based on `dart.library.html`.

## Configuration

Runtime config is loaded from `.env` at app startup via `flutter_dotenv`. The `.env` file is bundled as a Flutter asset. Key variables:
- `QUESTIONS_COUNT` — fallback count (default `25`) used before Firebase loads
- `ALLOW_REPETITIVE_PERSON_SCAN` — allow scanning the same person for multiple boxes
- `ALLOW_SAME_USER_SCAN` — allow a user to scan themselves

Firebase is initialized in `main()` with `firebase_options.dart` (auto-generated by FlutterFire CLI). The Realtime Database URL is hardcoded in `QuestionService`: `https://namma-bingo-d007c-default-rtdb.firebaseio.com/`.

## Design System

- **Colors**: `lib/const/app_colors.dart` — all palette entries and gradients. Dark navy theme (`background: #021B3A`).
- **Typography**: `lib/utils/typography_utils.dart` — `AppTypography` with responsive scaling via `AppTypography.scale(context, size)` relative to a 375 pt base width. Always use `AppTypography.*` style methods instead of raw `TextStyle` for consistency.
- **Font**: Outfit (Google Fonts), configured globally in `MyApp.theme`.

## Data Models

`lib/models/user.dart` defines two models:
- `User` — the current device user (name, linkedinUrl, profilePictureUrl, scannedBoxes as `Set<int>`)
- `BingoBox` — a single grid cell (id, isSelected, scannedBy details, questionAnswered, scannedAt)

Both use `copyWith` / `toJson` / `fromJson` patterns. `BingoBox` has no `fromJson` — deserialization is done inline in `BingoBoxesNotifier._loadBoxes()`.
